# 覆盖度与文案审计

## 内容来源

| 来源 | 说明 |
| --- | --- |
| 本机智能体日志目录（`PROMPT_LIB_LOGDIR` 环境变量指向的 `*.json`） | 约 1.9 万条历史使用记录，去重后约 1 万条，按频次提炼 |
| 本机笔记目录的「提示词」笔记 | 日常积累的提示词笔记 |
| 本机笔记目录的「泛化命令」笔记 | 可复用的工作指令块 |
| quick-paste 缓存 `data.json` | 常用短语分组 |
| 博客《个人使用的智能体提示词公开》 | 已公开的通用提示词分类 |

处理原则：**相似内容合并同类项**、**泛化与去占位符**（具体路径/课题/内部代号一律换成通用说法，正文复制即可粘贴）、**脱敏**（移除本机目录、个人标识、内部会话名与提交哈希）。

## 审计脚本

`_tools/` 下保留了审计脚本，用于每次增补后检查遗漏与重复：

| 脚本 | 作用 | 能否在 CI 跑 |
| --- | --- | --- |
| `content_audit.py` | 标题长度/雷同、正文近重复、标题与正文冗余度 | 能（卡口） |
| `style_audit.py` | 单句长度、顿号连排长度、交付物缺失、第 1 句是否只复述标题 | 能（卡口） |
| `desensitize_scan.py` | 专名残留扫描（期刊、学科、工具、路径、身份） | 能（卡口） |
| `i18n_audit.py` | 中英文切换巡检：英文译文是否覆盖全库、译文有无漏译中文、界面字典是否漏键 | 能（卡口） |
| `dist_check.py` | 产物自检：`dist/index.html` 引用的资源哈希与实际文件是否一致 | 不能（需先构建） |
| `gaps.py` | 用任务关键词探测日志，逐个核对库内是否覆盖 | 不能（需本机日志） |
| `heads.py` | 按指令开头聚类日志提示词，暴露低频但独立的任务方向 | 不能（需本机日志） |
| `dump.py` | 从日志提取全部提示词并按频次与项目分布统计 | 不能（需本机日志） |
| `make_assets.py` | 生成分享预览图与站点图标（`og.png` / `icon-180.png` / `favicon.ico`） | 不能（需 Pillow） |

四个卡口脚本发现问题时返回非 0 退出码，CI 会因此失败；其余脚本只产出报告。

脚本会把结果写进 `_tools/*.txt`（`content_audit.txt`、`style_audit.txt`、`kwcov.txt`）。
这些是自动产物，已加入 `.gitignore`，不进版本库。

### 公共模块

三个内容卡口脚本与日志脚本共用两个模块，避免同一套规则写三遍：

- `_tools/promptlib.py` —— 读提示词库的统一入口，解析规则来自 `build.py`
  （对代码块做了 fence 感知：正文里的 `## ` 不会被误判成新条目）。
  审计看到的条目，就是构建时看到的条目。
- `_tools/logload.py` —— 读本机日志的统一入口，噪声词表只有这一处。

`i18n_audit.py` 不走 `promptlib`：它对账的是 `src/i18n/en/` 里的英文译文 JSON 与
`src/assets/i18n.js` 里的界面字典，按条目 id 与字典键逐项核对。

### 日志目录怎么配

日志脚本需要本机日志目录，版本库里不写死任何本机路径。两种方式任选其一：

```bash
# 方式一：环境变量
export PROMPT_LIB_LOGDIR="D:\path\to\logs"

# 方式二：_tools/local_config.json（该文件已加入 .gitignore，不进版本库）
{"log_dir": "D:\\path\\to\\logs"}
```

两个都没配时，脚本会打印上面这段提示并退出，不会去猜路径。

### 关键词表与同义覆盖

`gaps.py` 里有一张 `KEYS` 表（161 个任务关键词），逐个核对日志里出现频次、
库内是否覆盖。两处需要注意：

- `ALIAS` 表记「同义已覆盖」：关键词字面没出现，但库内用通用说法收录了同一能力时
  （例如 `Docker` → 容器化、`sitemap` → 站点地图、`暗色` → 深色模式），算「同义已覆盖」
  而不是缺口，避免为了凑字面而重复写一条提示词。
  脚本每次运行都会核对 `ALIAS` 指向的条目标题是否还在库里——条目改名后
  会打印 `!` 提示，提醒回来改这张表。
- 改 `KEYS` 时注意别写重：重复的关键词会让同一方向在报告里出现两遍。

## 归档脚本

`_tools/archive/` 下是一次性脚本的历史存档（各轮整理时跑过一次，不再维护）：
`restructure_v2.py`（分类重排与条目合并）、`check_len.py`（改写后自检字数、空泛词、顿号连排与交付物）、
`readme_counts.py`（按 `src/prompts/` 实际内容重生成 README 的规模行与分类表格）、
`round4~6.py`、`round9*.py`、`migrate.py` 与 `migrate2~7.py`（历轮批量迁移脚本）、
`coverage.py`（按 n-gram 重合率判断覆盖，因库内条目统一改写后该信号噪声过大而归档）。
各脚本作用见 `_tools/archive/README.md`。
