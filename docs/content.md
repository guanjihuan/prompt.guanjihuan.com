# 提示词数据格式

## 新增一条提示词

编辑 `src/prompts/` 下对应分类的 Markdown：

```markdown
## 标题
<!-- id: p-<16 位哈希> -->
<!-- t: 标签1,标签2 -->

提示词正文使用一个自然段，写清做法、验收标准与交付物，**不用占位符**——复制即可直接粘贴；需要指定对象时在句内写明（如「用 Python 绘制」「按目标期刊的公开写作要求」「保留最近 7 份」）。
```

每条提示词都在标签后带一个 `<!-- s: 可直接使用的简洁提示词。 -->`（简洁表达）——卡片上的「简洁表达 / 详细表达」两个版本都靠它。确无更短说法时可以省略，但构建时会点名提醒：漏写的条目在卡片上只剩一个版本。

`<!-- id: -->` 是条目的**稳定标识**，必填且全库唯一。它决定收藏、使用次数和分享链接指向哪一条，因此一旦定下就不要再改：改标题、移动分类、调整顺序都不会影响它。

新增条目的 id 用 `p-` 加 16 位哈希（如 `p-e418db87a387eaba`），不要复用历史编号——
被合并或删除的条目，其旧编号已经作废（老链接可能还指向它们），复用会让收藏和分享链接指错条目。

新增分类则新建 `src/prompts/NN-<id>.md`，并在 frontmatter 里补齐字段：

```markdown
---
id: my-cat
name: 分类名
icon: "◇"
desc: 一句话说明这个分类覆盖什么
section: 软件工程
order: 12
---
```

`section` 决定它在侧栏归到哪个分区，`order` 决定全库分类的先后。构建时会校验：缺字段、图标重复、标题重复都会报错。

分区在侧栏里的**位置**不由分类的 `order` 决定（办公事务的分类是 42~49 号，按编号会排在最后），而是由 `build.py` 里的 `SECTION_ORDER` 表单独定：表里写着的分区按这个顺序排，没写进去的分区按分类首次出现的顺序接在后面。新增分区时按需往表里加一行。

新增或修改条目时，还要在与分类同名的 `src/i18n/en/NN-<id>.json` 中同步英文译文。每个条目按稳定 id 写 `title` / `tags` / `short` / `content` 四个字段，分类的英文 `name` / `desc` 也要同步；新增分区名时更新 `src/i18n/sections.json`。构建会核对文件集合、条目 id、字段、标签数量以及简洁表达有无，缺译或多译都会报错。可再运行 `python _tools/i18n_audit.py` 检查英文残留中文和界面字典漏键。

然后重新执行 `python build.py`。文案怎么写见 [philosophy.md](philosophy.md)。

## 脱敏与通用性

**每条提示词都不绑定任何具体项目、课题、期刊、工具或身份**，可以原样用在任何项目上：

| 原本会绑定的写法 | 通用写法 |
| --- | --- |
| `某期刊风格` | `目标期刊的公开写作要求` |
| `物理图像 / 物理概念` | `核心概念与机制图像` / `领域概念` |
| `CLAUDE.md` | `项目规范文件（如 CLAUDE.md）` |
| `写一份 .tex 综述` | `用 LaTeX 排版` |
| `用 [编程语言] 绘制` | `用 Python 绘制` |
| `名称、坐标、类型、长度、颜色、材料` | `名称、位置、类型、尺寸、外观与业务属性` |

`_tools/desensitize_scan.py` 会扫描专名残留（期刊、学科术语、工具名、本机路径、身份），要求**零残留**——具体对象用通用说法（目标期刊、目标平台）或「（如 …）」示例表达，需要指定对象时在句内写明（如「用当前代码复现一篇文献的图件与数值」）。

## 数据校验

`python build.py` 在构建时做数据校验并报错：

- 分类缺少 `id` / `name` / `icon` / `desc` / `section`、frontmatter 未闭合、未知字段
- 分类 `id` 重复、`order` 不是整数、分类内没有任何条目
- 条目正文为空、缺少标签、**缺少稳定 id**、id 重复
- **全库标题重复**（跨分类也会检出）、图标重复、图标与侧栏固定图标重复
  （全部 `✦` / 收藏 `★` / 自定义 `✚` / 用户自建分类 `▪`）
- 简洁表达不短于正文（与正文完全相同时视为没写，不报错）
- 缺简洁表达（`s` 字段）只提醒不拦构建，提醒里会点名是哪一条
- 英文译文文件与分类不对应、条目 id 缺失或多余、字段不全、标签数量不一致、简洁表达有无不一致
- 模板数据占位符未注入

图标另有「形近提示」：两个分类的图标字符不同但外形相近（如 `⊙`/`◎`、`⇄`/`⇆`、`✱`/`✻`）时，构建会打印一行 `!` 提示，不会中断构建——同族图标请尽量分散到不同分区。

校验不通过时不会清空 `dist/`，上一份可用构建原样保留。

解析器对代码块做了 fence 感知：正文里的 `## ` 不会被误判成新条目。
