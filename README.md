# GUAN 提示词库 prompt.guanjihuan.com

把需求说清楚，提示词就写好了。这里收录了 555 条按这个标准整理过的智能体提示词，覆盖工程、界面、文档、办公、求职、学术写作等日常场景，搜索即取、复制即用。

站点纯静态、无需登录：打开 [prompt.guanjihuan.com](https://prompt.guanjihuan.com)（尚未上线前可双击 `dist/index.html` 离线使用），左侧选分类或直接搜索，找到合适的条目一键复制，粘贴给任何智能体即可。

## 这些提示词怎么写的

每条提示词都是一段写清楚的需求：做什么、对谁、达成什么、怎么验收。判断一条写得好不好，只看五件事：

1. **直击问题**——第一句就说清要解决什么，不做铺垫，不写「为了……所以」。
2. **直击目标**——写明做到什么程度算完成，交付物与验收方式都落在正文里，不靠读者猜。
3. **简洁易懂**——一段话不超过 100 字（实测 65~100 字，中位数 92 字），用平实说法，不堆术语和黑话；不写「全面」「系统」「深入」这类空泛词。
4. **复制即用**——不设占位符，不留 XXX、待填、〈文件名〉这类要用户填空的地方；需要指明对象时在句内写死（如「用 Python 绘制」「按目标期刊的公开写作要求」「保留最近 7 份」），拿到手的任务上按实际情况改词就行。
5. **不绑定具体项目**——原始对话里的路径、课题、代号都换成通用说法，脱敏和通用化都不损失指令力。

| 写法 | 判断 |
| --- | --- |
| 「让同一件事只有一处实现。找出重复来源与职责交叉处，用调用关系确认后再合并。」 | 好：第一句给了目标，后面给做法 |
| 「找出重复劳动来源，定位职责交叉与边界不清的位置，用调用关系证实。」 | 不好：只有方法，达成什么要靠猜 |
| 「审计插件体系。」 | 不好：标题复述，等于没说需求 |

写一条新提示词时的体例细节（标题长度、正文句数、标签、两种表达）见 [docs/philosophy.md](docs/philosophy.md)。

## 站点功能

- 按分区与分类导航，全局搜索并高亮（不随分类收窄）；「全部提示词」页首列出全部分类便于点进，下面是随机顺序的提示词卡片，可「换一批」重排
- 一键复制单条；确有详略差异的条目同时提供「简洁表达」和「详细表达」两个版本
- 复制时可自动加任务命令（`/loop` 等四个常用命令，也可自定义），或从「工作指令块」分类选一个指令块追加到尾部，也可写自定义指令
- 收藏、复制次数统计、分享链接，数据都保存在本机浏览器
- 支持导入导出（Markdown / JSON），可添加自己的提示词
- 明暗主题、中英文全站切换（默认中文并记住选择）、键盘操作、移动端适配

## 构建与部署

```bash
python build.py            # 构建 dist/
python build.py --check    # 只做数据校验，不产出
python build.py --serve    # 构建后本地预览 http://127.0.0.1:8777
python build.py --out DIR  # 构建到指定目录，不动 dist/
python -m pytest tests/    # 回归测试
```

`dist/` 是纯静态产物，放到任意静态托管即可。部署步骤见 [deploy/README.md](deploy/README.md)。

提示词数据在 `src/prompts/`（一个 Markdown 文件一个分类），改完重新执行 `python build.py`。新增条目的格式、稳定 id 规则与校验项见 [docs/content.md](docs/content.md)。
